# 评审：Zven 站点信息架构 IA v0.1

> 文档性质：独立评审意见。只出意见，不改 IA 正文，不改母文档／分镜／用法。
> 评审对象：`docs/zven-site-information-architecture.md`（IA v0.1），分支 `cursor/zven-site-information-architecture-09a3`，PR #7。
> 对照上游（同分支 `docs/`）：母文档 `zven-lifecycle-dossier-philosophy-worldview-outline.md` v0.1.2；分镜 `zven-interactive-writing-storyboard.md` v0.1.1；用法 `zven-writing-desk-usage.md`；命名草案 `zven-lifecycle-dossier-naming-draft.md` v0.1.2；样本页 `samples/zven-sample-scenario-node-001.md`。
> 评审以 Human 已锁定项为准：助手名 Margo／玛戈；观察者无专名；元素 6 已取消；「陪写」／Companion-desk 为 Zven 轨助手暂名、未锁。本评审不推翻上述任何一项，也不代 Human 拍板任何开放项。
> 严重度：**阻断** = 不补则不宜开线框；**应改** = 应在 IA v0.1.x 修正，可与线框并行；**可记** = 记入待办，不挡线框。

## 总评

**有条件通过。** IA 与母文档、双轨用法没有硬冲突，也没有把母文档 §4 的待拍板项升格为站点已定；但站点地图缺了两个线框必须知道的位置关系（主题锚点／三态行在哪、公开子集与档案地址是不是同一套），补上这两处再开线框。

## 标准二：结构是否够下游线框

**结论：七项里五项够画，两项缺位置或缺关系，不补不宜开线框。**

逐项核对线框作者读完能否落笔：

| 线框需要画的 | IA 是否给了 | 依据 | 缺口与严重度 |
| --- | --- | --- | --- |
| 入口 | 部分 | IA §5 树与表 | 树上「入口」只通向写作桌；档案、可见性、公开子集是并列根节点，未说入口是否也通向档案／公开子集，也未说入口对作者与对读者是否同一处。见 2-B。**阻断** |
| 双过程面 | 基本够 | IA §1、§5、§6 第 1–3 条 | 缺一句：过程面上未落盘的内容（观察者草稿、Zven 层笔记、陪写对话）是否由站点持存、放在哪个非地址位置，还是「私聊」可能在站外。见 2-C。**应改** |
| 三种声音落位 | 够 | IA §1 声音表、§5 Node 行、§6 第 4 条 | 无缺口 |
| Dossier／Scenario／Node 地址 | 基本够 | IA §2、§5、§6 | Node 与 Scenario 在树上为并列，暗示 Node 地址不从属 Scenario，但未明说；若线框把 Node 画成 Scenario 的子路径，母 §4.7「多属」一旦拍板允许就要改地址。见 2-D。可记（一句话即可） |
| 可见性 | 部分 | IA §3、§5「可见性／发布」行 | 两层覆盖规则被写成「留给线框」。线框作者拿到的是一个政策决定，不是版式决定。见 2-E。**应改** |
| 三态同桌 | **缺位置** | IA §4 要求「读者停在一块场或一条锚点上时，三态的有无都能同时被读到」 | IA §5 站点地图里没有「主题锚点」或「三态行」的位置，§6 也没有到达它的路径。§4 的要求在 §5 没有落点。见 2-A。**阻断** |
| 公开子集 | **缺关系** | IA §5 树、§6 第 6–7 条 | 未说公开子集是同一套 Node 地址按可见性过滤后的视图，还是另一套位置。母 §3.4 每个 Node 一个持久地址；若公开后地址变了，引用与交接就断。见 2-B。**阻断** |

### 2-A 主题锚点／三态行在地图上没有位置 — 阻断

- IA §4 把三态同桌定为「站点要求，不是版式决定」，并说读者会「停在一块场或一条锚点上」。
- IA §5 的树与表列了入口、写作桌、两过程面、整卷、Scenario、Node、可见性、公开子集，没有锚点，也没有「同一锚点下的三态行」。IA §6 七条导航也没有通往锚点的一跳。
- 母 §2.3.2、§0.3：锚点是「三栏并置的依据」；母 §3.4 三栏并置是网站载体的核心含义；分镜 §2.1、§8.2 同。
- 同类缺位：母 §2.5 认知 × AI 时代索引「供日后横向检索」。IA §2 说它「不是单独的站点栏目」是对的，但没有说横向检索落在哪（整卷浏览内？Scenario 内？）。
- 需补：锚点／三态行是整卷浏览或 Scenario 内的一种视图，还是独立可达的位置；从 Node 如何到它所在的锚点行；时代索引的检索入口挂在哪。不需要画三栏，只需要给位置与到达路径。

### 2-B 公开子集与档案地址的关系；入口通向何处 — 阻断

- IA §5 树上，「公开子集」与「档案」是两个并列根节点；表中「公开子集｜放：已选出的 Node」。IA §6 第 6 条只说「公开子集里的一条，仍是那条 Node 的当前版本」，第 7 条说不认识样本的读者「只走公开子集」。
- 未说明：公开子集是否就是同一批持久地址在可见性过滤下的样子。母 §3.4「每个 Node 有一个持久地址。可被引用、可被链接、可被交接」「公开与私密的分层可以在地址层面实现」。若线框把公开子集画成另一套地址，一条 Node 从私密变公开时链接会断，交接律（母 §2.4 第 7 条）受损。
- 「入口」在树上只通向写作桌。对不认识样本的读者，入口通向哪里；对 Human，入口是否同一处。IA §0 说「按帽子分地址」，但入口这一层没分。
- 需补：一句「公开子集不是第二套地址，是同一套 Node 地址按可见性过滤后可被外部读者到达的部分」或等价的否定；入口对读者／作者分别下一跳到哪。这两句都是 IA 层的事，不是线框的事。

### 2-C 过程面上未落盘内容的持存与归属 — 应改

- IA §6 第 2 条「过程面不占用 Node 的持久地址」「尚未落盘的句子还不是一条 Node」，这是对的。但用法 §6 第 3 步「不提升的笔记**留在** Zven 层或私聊」、分镜 §4.5「笔记留在 Zven 层或私聊」——「留在」意味着有地方存。
- IA 没说：Zven 层是站点内一个无持久地址、不进公开子集的位置，还是「私聊」可能完全在站外；观察者过程面上的半成品（包括分镜 §4.4 所说三项不齐、暂不写入未来层的句子）落在哪、跨场是否还在。
- 线框作者若不知道这一点，要么把 Zven 过程面画成一个空壳，要么给它造一套地址。IA 只需回答「站内非地址位置／站外／未定」三选一，不需要描述任何界面。

### 2-D Node 地址不从属 Scenario — 可记

- IA §5 树上 Node 与 Scenario 并列，IA §2 允许 Node「暂时哪里都不属于」，IA §6 末句「任意一条已落盘的 Node 都可以被直接打开」。三处合起来已经推出 Node 地址独立于 Scenario，但没有一句直说。
- 母 §4.7 倾向允许一个 Node 属多块 Scenario，待拍板。若地址从属 Scenario，拍板允许时地址要重排。建议 IA 加一句「Node 的持久地址不以 Scenario 为前缀」，不涉及 URL 写法。

### 2-E 可见性两层覆盖规则的去向 — 应改（兼涉标准三）

- IA §3「两层如何互相覆盖，留给线框。本页不另造覆盖规则（分镜 §6）」。分镜 §6 第 2 拍原文相同。
- 覆盖规则是政策（谁更保守谁胜、还是 Scenario 覆盖 Node），母 §4.5 已锁定的只有「Node 级属性、Scenario 级可选、默认保守」，没锁覆盖方向。它不是版式决定，线框作者没有资格定，实际结果会是线框作者代 Human 拍板。
- 应改为：列入 IA §7「本页不锁定」，注明待 Human 拍板；线框前需要一个工作默认，由 Human 给。评审不在此替 Human 选方向。

### 2-F 导航边未列 — 应改

- IA §6 的七条覆盖了「轨 ↔ 档案」「档案 ↔ 公开」的移动，未覆盖档案内部的边：Node → 所属 Scenario；Node → 它所在的锚点行（见 2-A）；假说 Node ↔ 回访结果 Node（母 §2.3.6「关联原假说」）；关联 Node；同一地址的修订史各版本；撤回后留在地址上的标记。
- 这些边是母文档已定的概念关系，IA 只需列出「存在、双向或单向」，不需规定控件。缺了它们，线框作者会自行发明或漏画。

### 2-G 缺口的载体与可见性 — 应改

- IA §2「缺口……落在桌上或 Margo 边栏里」；IA §4「空着的一态是缺口」。母 §2.5 缺口可「被填补、被确认为永久空白、或被保留为待回访」——三种状态说明缺口有持存，不只是边栏里的一句话。
- 未说：缺口挂在 Node、Scenario 还是锚点行上；边栏折上之后（母 §2.2.2 边栏可折叠而不影响正文完整）缺口标记是否仍可见——沉默律（母 §2.4 第 6 条）要求空白被标记，若标记只在可折边栏里，折上即消失。
- IA 层只需回答缺口的载体（挂在哪个单位或锚点行上）与它是否随 Node 可见性一同公开。

### 2-H 公开子集是否含修订史 — 应改（列为开放项即可）

- IA §3、§6 第 6 条反复说公开的是「当前版本」。母 §3.1「修订史与假说回访让读者看见这卷档案随时间变化」把修订史当作作品对读者可见的一部分；母 §2.3.5「修订本身是内容而非元数据」。
- 「当前版本」在母文档里指 Dossier 没有完成态，不是指隐藏旧版。IA 未说一条公开 Node 的旧版本（含私密期写下的旧版）是否随之公开。母文档没定，IA 不应定，但应列进 §7。

### 3.2 IA 自行做出、但属 IA 职权的决定（不算越权，记录以便 Human 知悉）

- IA §5「可见性／发布……不是必经的一页」。母文档未定，属信息架构层的判断，与「写完只是进入当前版本，不是发布」（分镜 §6 第 1 拍）一致。
- IA §5「公开子集……可选。只含作者选出的地址」。「可选」宜理解为「可以为空」，而非「站点可以没有公开面」——母 §3.1 作品身份要求有可读面。可记，改一个词。
- IA §5 公开 Node「及其摘录与可折叠边栏」一并进入公开子集。母文档未逐字说边栏随 Node 公开，但母 §3.1「边注声是作品的一部分……可被折叠」支持。属合理推导，建议在 IA 里标明这是推导而非上游原文。
- IA §6 第 1 条「换面只换过程面，不把对面的助手带过来」。上游未逐字写，但由用法 §1「陪写不冒充 Margo 的边栏」、分镜 §4.5「Margo 只在观察者一侧开口」可推出。合理收紧。

## 给搭子转 Human 的摘要

1. IA v0.1 评审结论：**有条件通过**。与母文档 v0.1.2、双轨用法无硬冲突；未把任何待拍板项写成站点已定。
2. 已锁定项全部守住：Margo 只对观察者；观察者无专名；元素 6 无第六槽；陪写仍标暂名未锁；Gnomon／Tally 等未入站。
3. 开线框前必须补两处：一是主题锚点／三态行在站点地图上没有位置（IA §4 要求它，IA §5 没画它）；二是公开子集与档案是不是同一套 Node 地址没说清，不说清则公开一条会断链接。
4. 一处要改去向：可见性 Node 层与 Scenario 层「如何互相覆盖」IA 写成「留给线框」，这是政策不是版式，应回到你手上拍板；线框前需要你给一个工作默认。
5. 另需你知悉两项 IA 未列的开放项：「Zven」与实名公开到什么程度（母 §4.2）；样本与观察者能否在作品内直接对话（母 §4.8）——IA 沿三种声音不设对谈位，若你日后允许，地图要加位置。
6. 两处措辞要改：IA §2「不是第六种单位」（单位只有三种）；IA §5「不放陪写全文」（应为陪写的话一律不放）。
7. 其余为可记项：导航边、过程面未落盘内容的归属、缺口的载体、修订史是否随公开等，IA 补一句即可，不挡线框。
8. 本评审不改 IA 正文，不代你拍板任何一项。
