# 样本上下文库 · 维度与收录

> 文档性质：概念层操作说明。讲一件事：碎片怎样进入 Zven 的上下文库，落在哪几维，如何被组装成可读的上下文。不含界面、线框、代码、字段表结构。
> 上游：母文档 `docs/zven-lifecycle-dossier-philosophy-worldview-outline.md` **v0.1.2**；分镜 `docs/zven-interactive-writing-storyboard.md` **v0.1.1**；站点 IA `docs/zven-site-information-architecture.md` **v0.1**。写作桌用法 `docs/zven-writing-desk-usage.md` 是本篇的**次要入口**，见本页 §7。
> 版本：v0.1 草案。维度清单为**推荐未锁**；各维取值除已在母文档锁定者外，均为**推荐未锁／待拍板**。母文档标「待拍板」或「推荐未锁」的，本页不升格。
> 沿用：观察者无专名（「观察者」/ Observer）。助手 Margo · 玛戈只对观察者说话。元素 6 已取消，不留第六槽。标题、样本称呼、定位语推荐未锁。下文单独写「§」而无前缀时，指母文档。

## 0. 这一页管什么

母文档回答「为什么这样记录」，分镜排节拍，用法页讲怎么坐下写，IA 讲东西落在站点的哪里。这一页回答的是：**这一卷究竟在积攒什么，用什么把它撑起来。**

答案先说在前面：

- 积攒的是**碎片**——任何形式、任何来源、任何长度。输入不设限。
- 撑起来的是**维度**——每条碎片被打上多维标记，日后按维度拉出来，组装成能读的上下文。
- 中间有一道门，叫**收录标准**。筛选在这道门上，不在输入框上。
- 归维由系统自动或半自动完成，**Human 确认、改、拒**。系统只提议，不落笔。

本页与用法页不冲突，但主从有别：本页是主用法，用法页的双轨是可选的书写姿势入口（本页 §7）。

## 1. 作品本质：由碎片组装成的「我」

### 1.1 不是双轨叙事

「要留档还是要被听懂」这一问，曾是写作桌的第一个分岔（用法 §1，分镜 §4.5）。在本页里它**不是主叙事**。它只是坐下时可选的一个姿势问题，与「这条碎片进不进库、落在哪几维」无关。

把作品理解成「两条轨」太简单了。两条轨只回答一次落笔用第几人称、旁边是谁。它不回答这一卷在积攒什么。

### 1.2 作品是什么

这部作品的本质是：**人类样本 Zven 的知识库——他的全生命周期上下文——由信息碎片组装成的「我」。**

三个词拆开：

| 词 | 含义 | 上游依据 |
| --- | --- | --- |
| 知识库 | 库里存的不只是事件，而是判断、方法、项目、接触面、方向。它回答「这个个体怎么想、怎么做、在做什么、跟谁接触、朝哪里去」。 | §1.5「上下文档案：让任一时刻的样本可被理解所需的最小充分场」 |
| 全生命周期上下文 | 不设阶段关卡。童年、昨日、尚未发生的假说，都能成为碎片。三态并置，不排时间轴。 | §1.5、§2.3.2、分镜 §2.2 |
| 碎片组装成的「我」 | 「我」不是先写好的传记人物，是从碎片的多维交集里被读出来的。每次组装都是当前版本。 | §1.5「覆盖 ≠ 完整」、§2.5 Dossier 没有完成态 |

它仍然遵守母文档的全部十律（§2.4）。它不是传记、不是数据集、不是日记。

### 1.3 维度是骨架，人称与助手是姿势

叙事逻辑只有一条：

```
碎片  →  多维打标  →  组装成可读上下文
```

- **维度是骨架。** 一条碎片值不值得留、留下之后能被怎样读到，取决于它落在哪几维。没有维度，碎片只是堆积。
- **人称是书写姿势。** 第三人称正文、第一人称摘录，是落盘时的声音层取值（本页 §3.2 声音层），不是组织原则。
- **助手是书写姿势。** Margo 在观察者一侧整理；Zven 一侧可有另一位暂名助手。他们决定书写时旁边有谁，不决定库里有什么。

姿势可以换。骨架不因姿势而变。

## 2. 收录标准：输入不限，收录有筛

### 2.1 边界在哪

| 层 | 规则 |
| --- | --- |
| 输入 | **不设限。** 任何长度、语言、形式、来源、时态、人称。半句话、一张截图的文字、一段聊天原话、一条转述、一个还没想清楚的判断，都可以丢进来。输入不是落盘。 |
| 收录 | **有筛。** 一条碎片进入 Dossier 成为 Node（或并入既有 Node），须过收录标准，并至少落一个内容维（本页 §3.4）。 |
| 未收录 | 留在输入层。不进 Dossier，不进公开子集，不算缺口。缺口是「本应有上下文却无痕迹」的空白（§2.5），未收录的碎片是有痕迹而未归位。两者不同。 |

输入框前面不设门，是为了不让「值不值得写」这个念头在下笔前就把碎片拦掉。门在后面。

### 2.2 倾向记

收录看的不是事件大小，是**这条碎片能否回答「Zven 是怎样一个个体」中的某一点**。

倾向收录：

- **关键认知。** 对某事的判断、立场、依据；改判（原来怎么看、现在怎么看）；未决的判断也算。
- **项目同步。** 正在做、做过、想做的作品与项目：起意、进展、停摆、收束。同步是状态陈述，不是打卡。
- **心得方法。** 做事的方式、工具的用法、什么情形下有效、什么情形下失效。
- **能体现「怎样一个个体」的信息。** 一次很小的动作若透露了立场，也收。样本页里「删掉模型补上的后半句」（`docs/samples/zven-sample-scenario-node-001.md`）就是这类：事很小，落在人机边界与注意力上。
- **接触面。** 第三人与 Zven 相接触的那一面，用代号。
- **方向的痕迹。** 轨迹在哪里弯了一下；哪一段方向不明。不写成结论。

### 2.3 不倾向记

- **生活琐碎。** 只有「发生了」、不携带判断／方法／项目／接触面／方向的流水。吃了什么、去了哪、几点睡，若不带任何上述信号，不收。
- **每日必填表。** 前作的每日追踪维度已降级（附录）。本库不设任何必须每日填写的维。
- **对样本的建议、目标、打气。** 不干预律、反鸡汤律。
- **人生意义的结论句。** §1.6。
- **第三人的内心与代言。** 只写接触面（第三人律）。
- **真名。** 一律代号（§4.4）。

不倾向 ≠ 禁止。Human 确认要留的，仍然可收。「身体」「居所」这类母文档举过的锚点，若碎片带着信号，也不因为像生活而被拒。被拒的是不带信号的流水。

### 2.4 不确定时

先丢进输入层。系统提议归维时若落不到任何内容维，进「待归维」（本页 §5），不强行收，也不丢。

现场态仍是最贵的（§2.3.1）。一条粗糙但带信号的现场，好过一段事后补圆的判断。收录标准不要求碎片完整，只要求它有落点。

## 3. 维度

### 3.1 总览

维度分两组。**内容维**回答「这条碎片在说什么」；**结构维**回答「它如何坐进档案」。结构维中的四条是母文档 Node 必带字段或已锁定属性（§2.5、§4.5），列在这里是因为归维必须一并处理它们，不是本页新造。

| 组 | 维度 | 状态 |
| --- | --- | --- |
| 内容维 | 认知判断 | 推荐未锁 |
| 内容维 | 作品项目 | 推荐未锁 |
| 内容维 | 技艺方法 | 推荐未锁 |
| 内容维 | 关系接触面（代号） | 维度推荐未锁；代号规则已锁（§4.4） |
| 内容维 | 时代索引 | 维度已有（§2.5）；维度集合待拍板（§4.7） |
| 内容维 | 意义取向 | 维度推荐未锁；性质已定（§1.6 引力） |
| 结构维 | 时间态 | 已定（§2.3.1） |
| 结构维 | 证据档 | 字段已定；档数与命名待拍板（§4.3） |
| 结构维 | 声音层 | 已定（§2.2.2） |
| 结构维 | 可见性 | 已定（§4.5）；「仅交接人可见」仍开放 |
| 队列 | 待归维 | 不是维度。见本页 §5 |

清单可增删。增删的理由与程序见本页 §5.3。没有第六槽，也没有为「以后再想」预留的空维。

### 3.2 各维定义与取值示意

以下取值除注明「已定」者外，均为**示意**。示意是为了说明维度的性质，不是已拍板的枚举。

#### 认知判断

- **定义：** Zven 对某事怎么看。包括立场、判断依据、改判、未决。
- **取值示意（推荐未锁）：** 立场／依据／改判（旧判 → 新判）／未决。改判必须能指向旧判所在的碎片。
- **为何设：** Human 定调的首项。「怎样一个个体」首先体现在他怎么判断。
- **边界：** 判断是 Zven 的，以第三人称写入正文（「Zven 认为」），或以摘录保留原话。观察者自己的解释不进这一维，它是推断档的正文。

#### 作品项目

- **定义：** Zven 正在做、做过、想做的作品与项目。项目同步落在这里。
- **取值示意（推荐未锁）：** 项目代号（Human 指定）＋ 状态词：起意／进行／停摆／收束／回访。不设进度百分比，不设截止提醒。
- **为何设：** 项目是个体把认知与方法投入时间的地方。同步流水按项目拉出来，就是一条可读的项目史。
- **边界：** 状态是陈述，不是目标。「停摆」是事实，不是待办。项目代号与第三人代号分表，由 Human 维护，本页不预造。

#### 技艺方法

- **定义：** Zven 怎么做事。方法、工作方式、工具用法、心得。
- **取值示意（推荐未锁）：** 方法名（自命名）／适用场／失效条件。
- **为何设：** 与认知判断相对：认知是怎么看，技艺是怎么做。两者常在同一条碎片里，所以分成两维而不合并——合并后无法单独拉出「方法史」。
- **边界：** 心得不写成对样本的建议。「Zven 发现 X 在 Y 情形下有效」可以，「Zven 应该多用 X」不行。

#### 关系接触面（代号）

- **定义：** 第三人与 Zven 相接触的那一面。
- **取值：** 代号。**已锁**（§4.4）：相对样本 Zven 的代号；寻常之人按与样本的关系，特别的人用特别代号；真名不进正文。一条碎片可挂多个代号。
- **为何设：** 一个个体大半由他的接触面构成。按代号拉出来，读到的是「Zven 与此人的那一面」的历史，不是此人的传记。
- **边界：** 只写接触面。不推测内心，不代言（第三人律）。代号表由 Human 维护。样本页的「同事甲」「友人·烛」是占位，不是正式代号。第三人能否请求撤回相关 Node 仍开放（§4.4）。

#### 时代索引

- **定义：** 母文档 §2.5 的「认知 × AI 时代索引」。横切的时代维度，只在碎片触及时标记。
- **取值示意（母文档示意，待拍板）：** 注意力／人机边界／知识代谢／记忆外包。
- **为何设：** §2.5 给了两条理由：Zven 生活的年代恰是人机边界被重构的年代；作品自身的记录者配有 AI 助手，索引让作品对自身处境自反。本页只把它接进维度表，不改定义。
- **边界：** 索引不是表格，不要求每条碎片都有值。集合待拍板（§4.7）。

#### 意义取向

- **定义：** 引力（§1.6）在碎片上的痕迹。轨迹在此处弯了一下，或此处方向不明。
- **取值示意（推荐未锁）：** 方向标记（Human 自命名的方向词）／弱区／未标。
- **为何设：** 引力只以结构方式存在——在选择里、在停留里、在沉默里。要让它可被日后回看，需要一个能被标记、能被拉出的位置。这一维就是那个位置。
- **边界：** **不得写成结论句。** 「人生的意义是什么」在正文中不以陈述句出现（§1.6）。方向标记会被修订、会被降格，弱区如实标记不填补。这一维的值越少越好，多了就成了鸡汤。

#### 时间态（已定）

- **定义：** §2.3.1 三态：溯源／现场／假说。同时带事件时间与档案时间两轴（§2.3.3）。
- **规则：** 假说态必带三项：假说内容、回访时间点、怎样算不成立。三项不齐不作为假说态写入。溯源是「现在如何记得过去」。
- **归维时：** 系统可从碎片内容推断时态并提议；事件时间缺失时提议为缺口，不补造日期。

#### 证据档

- **定义：** 碎片与「发生的事」之间的距离（§2.5、证据律）。
- **取值示意（母文档示意，待拍板）：** 现场／近场／回忆／转述／推断。档数与命名未锁（§4.3）。
- **归维时：** 系统按两轴时间的距离与来源提议一档；推断不得借现场外观。摘录如何定级仍开放，拍板前照样带一档并允许复核。

#### 声音层（已定）

- **定义：** §2.2.2 三种声音：正文声（观察者）／摘录声（样本）／边注声（Margo）。
- **规则：** 碎片若以第一人称收录，只能成为摘录声，必带时间、证据档、「样本自述摘录」标记。改写为第三人称的，成为正文声。归维提议本身不是第四种声音（本页 §4.2、分镜 §8.1）。
- **为何列入维度：** 组装时必须知道每片在哪一层说话，否则组装出来的读本会混声。

#### 可见性（已定）

- **定义：** §4.5 分层发布。Node 级属性，Scenario 级可选，默认保守。
- **取值：** 默认不对外／作者选出公开。「仅交接人可见」是否存在仍开放，本页不预设那一档。
- **归维时：** 系统只能给默认值，不能提议公开。公开由 Human 逐条选。

### 3.3 不是维度的东西

- **主题锚点**（§2.3.2）不是维度。它是横穿三态的一条主题线，用来把三态拉到同一行。维度标记可以帮助系统**提议**某条碎片归入某个锚点，但锚点初始集合待拍板（§4.7），本页不代决，也不把锚点列成一维。
- **Scenario** 不是维度取值。它是「一组可以互相解释的 Node 构成的场」（§2.5）。维度相同的碎片不自动成为一个 Scenario；成场由 Human 决定（本页 §6.1）。
- **情绪、饮食、位置、应用使用**等前作每日维，不设为维度（附录）。带信号的相关碎片可落在认知判断、技艺方法或时代索引上。
- **元素 6。** 已取消（§4.1）。维度表不留第六槽，「待归维」不是它的替身。

### 3.4 一条多维

1. 每条收录的碎片**必带全部四个结构维**（其中可见性取默认即可）。这与 Node 必带字段一致（§2.5）。
2. 每条收录的碎片**至少落一个内容维**。落不到的进待归维，不强收。
3. 内容维**可多选**，不设上限。同一维内可多值（一条碎片挂两个代号、两个项目）。
4. 多维不等于重复。同一条碎片只有一个持久地址（IA §2），多维标记都打在这一个地址上。
5. 维度标记本身有修订史。改一次标记，是一次新的观看（§2.3.5）；旧标记可查。

示意：样本页那一晚的碎片，可落 **认知判断**（未决：写完的那个人还是不是我）、**技艺方法**（断句交给模型、删去补全）、**时代索引**（人机边界）、**意义取向**（弯了一下，未标方向词）、**关系接触面**（同事甲、友人·烛，占位代号）；结构维为现场・近场・正文声＋一条摘录声・默认不对外。五个内容维同挂一条地址。

## 4. 归维流程：系统提议，Human 确认改

概念层。不规定界面、按钮、字段名。

### 4.1 步骤

```
输入（不限）
  → 系统归维提议（自动／半自动）
  → Human 确认／改／拒／移入待归维
  → 落盘：新 Node，或并入既有 Node（修订或摘录）
  → 组装：按维拉出，读成上下文
```

1. **输入。** 任何形式的碎片进入输入层。不问人称、不问时态、不问完不完整。
2. **系统提议。** 系统对每条碎片给出一组维度提议。分两类：
   - **自动**（无需确认即可作为默认）：档案时间；可见性默认值；语言识别；已在代号表中的代号匹配；已在项目表中的项目代号匹配。
   - **半自动**（须 Human 确认）：内容维归属；时间态；证据档；事件时间的推断；新代号或新项目代号的候选；锚点或 Scenario 归属的提议；新维度候选（只入待归维汇总，不直接成维）。
3. **Human 处理。** 对每项提议：确认、改、拒，或把整条移入待归维。拒是完整的操作。忽略也是。
4. **落盘。** 确认后的碎片成为一条 Node，带持久地址；或作为修订并入既有 Node；或作为「样本自述摘录」嵌入某条正文。未确认的提议不落盘。
5. **组装。** 见本页 §4.3。

### 4.2 归维的边界

- **系统只提议，不落笔。** 权限流向（§2.2.4）：Human 有书写权，系统只有提议权。没有一条标记不经 Human 而进入 Dossier。
- **归维拓展。** 系统可以提议新取值（新项目代号、新方法名、新方向词）与新维度候选。取值由 Human 确认后即可用；**新维度只能经本页 §5.3 升维程序**，不能由系统直接开。
- **提议的声音归属。** 归维提议本身不带声音。
  - 在输入层（样本一侧），提议只是标记，不说话，不称呼 Zven，不评价内容。系统不在样本侧扮演任何角色。
  - 在档案一侧，若提议需要被解释（为何归此维、证据档为何是这一档、缺口在哪），它以 **Margo 边注**的形式对**观察者**出现（§2.2.1、助手边界律）。Margo 不进样本侧，不对 Zven 说话。
  - 提议不是第四种声音（分镜 §8.1）。
- **不催促。** 归维不产生「待处理数」式的提醒，不催 Human 清空队列。持久优先于催促（§3.4）。
- **不补造。** 事件时间缺失、来源不明、判断未决，都如实标为缺口或未决。系统不为凑齐字段而编造。
- **置信度。** 系统对半自动提议可附一个置信标注（示意：高／低）。档位与是否显示，**推荐未锁**。低置信的提议默认导向待归维而非强归。

### 4.3 组装成可读上下文

组装是**读法**，不是新单位。它不产生第四种档案单位，也不改变任何 Node 的地址。

- 按一维拉出：某个代号下 Zven 与此人接触面的全部碎片；某个项目的同步流水；某一判断的改判史；某个方向词下的所有弯折。
- 按多维交集拉出：某项目 × 人机边界；某代号 × 某一时期的溯源态。
- 组装出的读本仍由三种声音构成：正文第三人称，摘录第一人称带标记，Margo 边注可折叠。
- 组装结果是当前版本。同一组维度在不同时刻组装出来的「我」可以不同。这个不同本身是内容。
- 若观察者在组装后另写理解，那是一条新 Node，带推断档，不改被组装的旧碎片。

三态并置（§2.3.2）是组装的一种：以主题锚点为行，三态为列。维度标记是锚点提议的依据，不替代锚点。

## 5. 待归维

### 5.1 什么进队列

- 过了收录标准（值得留），但落不到任何现有内容维。
- 系统提议置信低，Human 一时未决。
- 系统判断它像一个新维度的样子，但这个维度还不存在。
- Human 主动放进来的：先留着，以后再看。

进队列的碎片**不是缺口**（缺口是无痕迹处），也**不是未收录**（它已过门）。它有痕迹、已过门、暂无落点。

### 5.2 队列的规则

- 队列里的碎片仍带全部结构维（时间态、证据档、声音层、可见性默认）。缺的只是内容维。
- 队列不对外。可见性停在默认。
- 队列不设上限，不设清空期限，不催。
- 队列里的碎片可以被引用（它已是一条有地址的记录），但组装时不按内容维被拉出，因为它没有。

### 5.3 升维：从队列到新维度

新维度只从这里产生。程序（推荐未锁，由 Human 拍板）：

1. **同型积累。** 队列中反复出现同一类落不到现有维的碎片。多少条算「反复」，本页不锁数字。
2. **Human 判断。** 这一类是否能回答「Zven 是怎样一个个体」中的一点，且与现有六个内容维不重合、不能靠给现有维加取值解决。
3. **命名与理由。** Human 为新维命名，写下设立理由与边界（对照本页 §3.2 每维的四项：定义、取值示意、为何设、边界）。理由写进本页的修订记录。
4. **回填。** 队列中同型碎片重新归维；既有 Node 中可能落入新维的，由系统提议、Human 确认。
5. **状态。** 新维初始为推荐未锁，与其余内容维同。

反向同理：某内容维长期无碎片落入，或与另一维持续重合，Human 可合并或撤销，理由同样写进修订记录。撤销一维不删碎片，只去掉标记；标记的修订史留着。

系统可以在队列里做同型汇总并提议「这里像一个维度」。它不能自己开维。

## 6. 与档案单位、声音、可见性、双语的关系

对齐母文档已定项。本页不越权代锁。

### 6.1 Dossier／Scenario／Node

| 单位 | 与本页的关系 |
| --- | --- |
| Dossier | 整个上下文库就是这一卷。只有一个样本、一卷档案。不出现其他样本、其他观察者（§2.1）。维度是这一卷内部的骨架，不是分卷依据。 |
| Scenario | 场，不是标签。维度相同不自动成场；Human 命名一块场，把互相解释的 Node 放进去（§2.5）。系统可基于维度交集**提议**成场，只是提议。一个 Node 可否多属 Scenario 仍待拍板（§4.7），本页按 IA 的「属于一处，或暂时哪里都不属于」来写。 |
| Node | 碎片收录后的形态。维度标记打在 Node 的持久地址上（IA §2）。Node 必带字段（时态、两轴时间、证据档、修订史）即本页的结构维加修订史。回访结果是新 Node，原假说不改（§2.3.6），两条各自带标记。 |

### 6.2 三种声音

- 声音层是结构维之一（本页 §3.2）。收录时定：第一人称原话 → 摘录声；改写第三人称 → 正文声。
- Margo 边注声在本页里承担一件事：把归维提议**对观察者**解释出来。它不进正文，不进样本侧，不对 Zven 说话。
- 没有第四种声音。归维提议、待归维汇总、组装读本，都不是新的说话区。

### 6.3 可见性

- 可见性是结构维之一，Node 级，默认保守（§4.5）。Scenario 级可选。
- 系统不提议公开。公开是 Human 逐条的选择。
- 组装读本的可见性等于其中每条 Node 各自的可见性。不因为被组装在一起而升格。公开子集只含已选出的地址（IA §5）。
- 「仅交接人可见」是否存在仍开放。本页不为它预设取值。
- 抹除只在第三人隐私与样本明确撤回两种情形，留下「此处曾有一条记录被撤回」（修订律）。维度标记随之去掉，标记的修订史保留。

### 6.4 双语

- 允许双语（§4.9）。碎片以什么语言进来就以什么语言留着；摘录保留原语言。
- 维度名与取值可双语并列。本页各维的英文 gloss **不锁**，由 Human 日后指定。
- 语言不是维度。系统可以识别语言，但语言识别只是输入层的自动标注，不进入内容维。

## 7. 与双轨、Margo、陪写的关系：姿势与次要入口

### 7.1 主从

- **本页是主用法。** 主流程是本页 §4：碎片进来、归维、确认、落盘、组装。
- **用法页是次要／可选入口。** `docs/zven-writing-desk-usage.md` 讲的是坐下写时的两条轨——以观察者执笔配 Margo，或以 Zven 第一人称配另一位暂名助手。它回答「这一次用哪个姿势写」，不回答「库里有什么、按什么撑起来」。
- 两页不冲突。用法页 §2「过程可以混，落盘要收回格式」、§3「记什么不记什么」、§4「第三人代号」、§5「分级发布」在本页均有对应并加严。用法页 §1 把双轨当作下笔前的第一问，本页不采纳这一叙事顺序：第一问是收录与归维，人称是落盘时才定的声音层。

### 7.2 双轨在本页里的位置

- 观察者轨与 Zven 轨都只是**输入方式**。从哪条轨进来的碎片，都进同一个输入层，过同一道收录标准，归同一套维度。
- 从 Zven 轨进来的第一人称碎片，若收录，或作为摘录声保留原话，或由 Human 改写为第三人称正文。用法页 §6 的「提升」在本页里就是这一步归维与落盘。
- 「要留档还是要被听懂」可以问，也可以不问。不问时，直接丢进输入层。

### 7.3 Margo

- Margo 仍是唯一的边注声，仍只对观察者。它在本页的职能不变：缺口、证据、回访、时间对齐（分镜 §4.2），外加把归维提议解释给观察者。
- Margo 不是归维系统的名字。系统在样本侧无声；只有需要对观察者说话时，才以 Margo 出现。
- Margo 不催归维，不催清队列，不对样本说「你应该记」。

### 7.4 陪写

- Zven 轨的助手暂名「陪写」/ Companion-desk，**暂名未锁**，不是正式产品名，本页不锁它。
- 它不参与归维，不打标记，不进 Dossier，不进边栏。它的话留在 Zven 层或私聊（用法 §2 第 4 条）。
- 若 Human 日后不用 Zven 轨，本页的主流程不受影响。
